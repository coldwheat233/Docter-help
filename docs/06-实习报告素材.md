## 一、项目定位（一句话）

基于 LangGraph 框架，构建可演示的多智能体医疗预约系统，对比 Supervisor 与 Swarm 两种编排模式，实现 100% HITL 关键操作把门。

## 二、核心技术栈

- **框架**：LangGraph 0.3+ / LangChain 0.3+
- **多智能体编排**：langgraph-supervisor 0.0.15 / langgraph-swarm 0.0.14
- **LLM**：DeepSeek（deepseek-chat）
- **可观测**：LangSmith
- **存储**：SQLite（5 张表）
- **HITL**：LangGraph `interrupt()` + `Command(resume=...)`
- **依赖管理**：conda + pyproject.toml

## 四、面试高频问题准备

### Q1：为什么选 Supervisor 不选 Swarm？

**答**：医疗预约是流程型 + 强 HITL 业务。

- Supervisor 中心化决策可控性强，HITL 接入简单（1 个图节点 vs Swarm 的 4 个 Agent 分散埋点）
- Swarm 灵活但易漂移，Agent 之间循环 handoff 风险高
- 详细对比见 `docs/03-supervisor-vs-swarm-对比报告.md`

### Q2：HITL 怎么实现？100% 把门怎么保证？

**答**：用 LangGraph 的 `interrupt()` + `Command(resume=...)`。

```python
from langgraph.types import interrupt, Command

def human_confirm_node(state):
    decision = interrupt({"type": "appointment_confirm", ...})
    return {"status": "confirmed" if decision == "approve" else "cancelled"}
```

100% 把门靠两点：
1. **图结构约束**：`set_appointment` 工具的节点在 `human_confirm` 之后
2. **代码审查**：`tools/appointment.py` 的 3 个写操作工具在文档里明确标注"必须 HITL"

### Q3：怎么防 LLM 幻觉？

**答**：3 层防护：

1. **关键字段格式校验**：`department` 必须在 `departments` 表里，`schedule_id` 必须存在
2. **HITL 100% 确认**：落库前必经人工
3. **日志 + LangSmith 追踪**：所有 LLM 调用留痕

### Q4：项目用 DeepSeek 不用 GPT 原因？

**答**：预算 ¥50 限制下，DeepSeek 价格优势明显（约 GPT-4 的 1/30）。但项目用 `langchain-deepseek` 官方包，模型层是抽象的，切换 OpenAI 只需改 1 行代码。

### Q5：项目遇到的最大困难？

**答**：D 盘空间紧 + Python 3.13 兼容性未明确。解决：

- 把 conda env 装到 C 盘（`miniconda3\envs\medical-appointment`）
- 用 Python 3.11（已存在 `python311` 环境）规避 3.13 兼容风险
