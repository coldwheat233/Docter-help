## 二、4 个子 Agent 分工

| Agent | name 唯一标识 | 输入 | 输出 | 工具 | LLM 调用 |
|---|---|---|---|---|---|
| **Router** | `router_agent` | 用户原始 query | `intent` (consult/book/reschedule/cancel) | 无 | 1 次/轮 |
| **Intake** | `intake_agent` | 多轮对话 | `symptoms` / `duration` / `severity` / `department` | `list_departments` | 多轮直到字段收齐 |
| **Scheduler** | `scheduler_agent` | 字段已齐 + 用户偏好 | `recommended_slots`（3-5 个） | `check_availability` / `list_doctors` | 1 次 |
| **Confirmer** | `confirmer_agent` | 用户选定时段 | `appointment_id` + 落库 | `set_appointment` | 1 次 + HITL |

### 调度规则（写在 Supervisor 的 prompt 中）

1. **首条消息** → `router_agent`
2. **意图 = book + 信息未全** → `intake_agent`
3. **信息已全 + 需要看时间** → `scheduler_agent`
4. **用户已选定时段** → `confirmer_agent`（触发 HITL）
5. **咨询类问题** → Supervisor 直接回答，不路由

## 三、State 流转

`AppointmentState` 贯穿全流程，关键字段变化：

```
[init]
  │  user_input: "我想挂号，胃疼"
  ▼
[intake]
  │  symptoms="胃疼", department="消化科"
  ▼
[schedule]
  │  recommended_slots=[5 个]
  ▼
[confirm]  ← HITL 暂停
  │  pending_human_confirm=True
  │  人工 Command(resume="approve")
  ▼
[done]
  status=confirmed, appointment_id="A20260901XXXX"
```

### State 字段定义（详见 docs/02-接口契约.md）

- **消息**：`messages`（LangGraph add_messages reducer 自动累加）
- **身份**：`patient_id`
- **问诊**：`symptoms` / `duration` / `severity` / `department`
- **排班**：`preferred_date` / `preferred_time_slot` / `recommended_slots` / `selected_slot`
- **流程控制**：`intent` / `current_step` / `pending_human_confirm`
- **输出**：`appointment_id` / `status` / `final_answer`

## 四、HITL（Human-in-the-Loop）接入点

**关键：所有写操作前必须人工确认**

### 接入位置

`confirmer_agent` 工具调用前（`set_appointment` / `cancel_appointment` / `reschedule_appointment` 三个工具）

### 实现机制

```python
from langgraph.types import interrupt, Command

def human_confirm_node(state):
    # 暂停图执行，推送详情给人工
    decision = interrupt({
        "type": "appointment_confirm",
        "patient_id": state["patient_id"],
        "department": state["department"],
        "doctor": state["selected_slot"]["doctor_name"],
        "datetime": state["selected_slot"]["schedule_date"] + " " + state["selected_slot"]["time_slot"],
        "ask": "是否确认预约？(approve / reject:原因)"
    })
    # decision 由 Command(resume=...) 注入
    if decision == "approve":
        return {"pending_human_confirm": False, "status": "confirmed"}
    else:
        return {"pending_human_confirm": False, "status": "cancelled"}
```

### 调用模式

```python
# 1) 第一次 invoke：会卡在 human_confirm_node
result = app.invoke({"messages": [...]}, config=config)
# 读取 state.next 知道停在哪
print(app.get_state(config).next)  # ('human_confirm',)

# 2) 人工审批后用 Command 恢复
final = app.invoke(Command(resume="approve"), config=config)
# 或拒绝
final = app.invoke(Command(resume="reject:不想等了"), config=config)
```

### 与 checkpointer 关系

- **必须**配 `checkpointer=InMemorySaver()`，否则 resume 拿不回上下文
- 演示用内存 saver；生产可换 PostgresSaver

## 五、对比实验：Supervisor vs Swarm

详细对比见 `docs/03-supervisor-vs-swarm-对比报告.md`，本节给结论：

| 维度 | Supervisor（主） | Swarm（对比） |
|---|---|---|
| 路由主体 | Supervisor 节点 LLM | 当前 Agent 自己 |
| HITL 接入 | ✅ Supervisor 节点统一拦 | ⚠️ 每个 Agent 都要埋点 |
| 状态管理 | ✅ 集中在 StateGraph | ⚠️ 分散 |
| 医疗场景适配 | ✅ 流程型强可控 | ⚠️ 灵活但漂移风险 |

**结论**：医疗预约流程型 + 强 HITL → Supervisor 完胜。

## 六、SQLite 集成

5 张表（详见 docs/04-数据库设计.md）：

- `departments`：科室
- `doctors`：医生
- `schedules`：排班（核心：每条 = 某医生某日某时段）
- `patients`：患者
- `appointments`：预约

工具函数通过 `Repository` 类访问（不直接写 SQL 在工具里）：

```
Tool 函数 (LangChain @tool)
    ↓
Repository 方法
    ↓
sqlite3.Connection
```

## 八、错误处理与降级

| 场景 | 降级策略 |
|---|---|
| LLM API 限流 | Supervisor 返回"系统繁忙，请稍后再试" |
| 排班库存不足 | Scheduler 返回"该时段已满"，重新推荐 |
| 关键字段格式错误 | 字段校验失败，Intake 反问 |
| HITL 拒绝 | Confirmer 把状态改回 pending，回复"已取消" |
| 数据库错误 | 上抛异常，落到日志，由人工兜底 |
